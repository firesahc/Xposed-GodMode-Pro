## 状态定义

- `IMPLEMENTED`：生产行为已实现，列出的自动化证据已通过。
- `ALREADY_SATISFIED`：基线已经具备目标行为。
- `DEFERRED_NEEDS_REPRO`：没有可重放复现或缺少所需设备证据。
- `EXCLUDED`：改变稳定合同，不进入本分支。

证据结果只使用 `JVM/STATIC PASS`、`AndroidTest COMPILED/PASS`、
`INSTRUMENTATION PASS/BLOCKED/NOT_RUN` 和 `DEVICE PASS/BLOCKED/NOT_RUN`。

术语以 [`CONTEXT.md`](../CONTEXT.md) 为准。尤其要区分：

- 产品断言或产品异常构成 `产品失败`；
- 宿主未启动、runner 被系统终止或超时属于 `基础设施中断`；
- 基础设施中断不得记为 PASS，也不得在没有产品堆栈时直接归因于产品代码；
- instrumentation 通过只证明对应自动化行为，不等同于最终设备发布验收。

## 独立验收宿主

`test-target/` 使用自己的 `settings.gradle`，通过根 wrapper 运行
`gradlew.bat -p test-target ...`。它不加入生产构建，也不包含规则逻辑。
宿主固定提供普通 View、margin/alpha、120 项纵向 RecyclerView、两种 item
类型、嵌套横向 RecyclerView、dataset refresh、adapter replacement、快速滚动和
Activity recreate 操作。

## Instrumentation 测试拓扑

MIUI/HyperOS 可能阻止 instrumentation 从后台启动 Activity，直接使用
`ActivityScenario.launch()` 会出现宿主未启动或 runner 被系统终止。稳定线使用以下
测试拓扑，避免依赖图片识别、坐标点击或逐帧截图：

- App 测试 Activity 位于 `app/src/debug/`，只进入 debug APK，不进入 release APK。
- Engine 测试 Activity 位于 `engine/src/androidTest/`，只进入 Engine 测试 APK。
- runner 先启动并等待宿主；脚本再通过 root 将明确的测试 Activity 置于前台。
- 测试通过 lifecycle monitor 获取处于 `RESUMED` 的 Activity，并在主线程执行断言。
- 每个测试方法使用独立 instrumentation 进程，避免 Activity、View 和 applier 状态串扰。
- 脚本只对明确的基础设施中断最多重试三次；出现断言堆栈或产品异常时立即失败。

设备执行前保持亮屏、解除锁屏，测试期间不要按返回键、切换应用或并行运行其他
Gradle/ADB 流程：

```powershell
adb shell input keyevent KEYCODE_WAKEUP
adb shell wm dismiss-keyguard
adb shell svc power stayon true

powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts/run-engine-instrumentation.ps1
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts/run-app-instrumentation.ps1
```

`run-engine-instrumentation.ps1` 当前执行 6 项应用器测试，覆盖 baseline、属性所有权、
重复应用、recycle、图片请求代次和 Activity state 清理。`run-app-instrumentation.ps1`
当前执行 7 项 controller 测试，覆盖修改/移除撤销、实际应用目标、detach/rebind、
Activity recreate 和同动作不同目标隔离。

不要将脚本与构建任务并行执行。构建或安装可能替换正在运行的 APK，导致 runner
被终止；此类结果只能记为基础设施中断。

两个脚本以 `am instrument` 原始输出中的测试数量、`OK` 和终态代码判断结果，当前
不会生成 Gradle/JUnit XML。开发阶段可以据此定位行为，但候选冻结后的发布证据仍
必须保存完整原始输出并生成或收集 fresh XML；不得把本轮控制台摘要冒充候选证据。

## 当前证据

自动化结果必须在最终候选 SHA 上重跑。开发阶段当前边界为：

| 层级 | 当前结果 | 说明 |
| --- | --- | --- |
| JVM/STATIC | PASS | app、engine 完整 JVM 测试和静态合同 |
| AndroidTest | COMPILED | 当前工作树已编译；此前设备结果来自不同候选，不绑定本轮 SHA |
| Debug APK | PASS | 生产 APK 与独立宿主 APK 可构建 |
| Lint | PASS | 生产 app 与独立宿主 |
| INSTRUMENTATION | NOT_RUN | 本轮 IPC/Repository/Recycler 修复尚未在同一候选 SHA 产生 fresh XML |
| DEVICE | NOT_RUN | 本轮修复尚未在同一候选 SHA 完成 system_server/Binder、Recycler、备份和重启矩阵 |

历史开发测试设备为 Xiaomi/HyperOS、Android 15。曾观察到两类无产品堆栈的中断：
`Test host Activity was not started` 和 `shortMsg=Process crashed`。在保持宿主前台
并改用上述测试拓扑后，Engine 6 项一次通过；App 7 项串行通过，其中 detach/rebind
用例首次遭遇基础设施中断、第二次取得通过终态。该事实用于改进测试运行方式，不得
用于关闭尚未执行的 DEVICE 项。

## 候选与发布

1. 所有实现、JVM、AndroidTest 编译、assemble、lint 和静态合同通过。
2. 将版本一次性改为 `52 / 6.9.0` 并提交，得到候选源码 SHA。
3. 从该 SHA 构建模块 APK、AndroidTest APK 和独立测试 APK。
4. 将文本证据写入 `docs/evidence/6.9.0/<candidate-sha>/`；证据提交不得修改构建输入。
5. 同一候选完成 instrumentation 和 DEVICE 验收，必需项全部 PASS 后才能创建 `v6.9.0` tag。

任何 Runtime、Recycler、图片、备份或 Binder 必需项为 `BLOCKED` 或 `NOT_RUN`
时均不得打 tag，也不得用编译、JVM 或旧候选结果替代。

## v6.9.0 后缺陷修复候选

`.omo/6.9后三提交分析.md` 是本轮审计输入，不是稳定合同或发布证据。代码审计修正了
两处推演：服务返回伪空规则时，`RuleManager` 先替换缓存再发事件，旧 View 效果通常不会
被立即撤销，结果是内存规则清空而运行时效果残留；单条删除竞态主要发生在“已有带图规则
修改后立即删除”或同目标快照并发，空缓存的新规则删除可能直接返回未找到。另确认两项遗漏：
规则事件发布前替换快照会丢失真实差异，`RuleServiceClient` 原先不保留观察者订阅，Binder
死亡重连后不会自动重新注册。

本轮候选修复保持 `RuleRecord`、ZIP V1、AIDL/Parcelable、生产模块拓扑和 `52 / 6.9.0` 不变：

- 服务 LOADING/ERROR 的 `getRules()` 返回 `null`，加载成功后向已注册观察者发送 ready snapshot；
  RuleManager 先发布变更事件再替换快照，客户端重连后幂等恢复 observer 注册。
- 单条快照写入登记并复制规则，在图片 I/O 前后及缓存 apply 前检查取消；删除在同一 mutation
  lock 下取消同目标 pending 写，避免删除后规则或新图片复活。
- RemoveApplier 的幂等判断同时检查 visibility、alpha、clickable；备份只修改导出副本，
  `RuleRepository` 克隆入口规则并以独立 package 参数归一化。
- Recycler token 删除无用途的数值 epoch，afterBind/recycle 核验 adapter、holder、itemRoot
  和 viewType；Activity 销毁先移除 token、取消 attach listener，再清理 controller。

本节的 `IMPLEMENTED` 只表示生产代码已实现且 JVM/编译门禁通过；本轮
`INSTRUMENTATION` 与 `DEVICE` 在同一候选 SHA 上执行前均保持 `NOT_RUN`，不得继承旧候选的
控制台摘要或缺少原始 XML 的 PASS 结论。
